# Skill: Generate Business Rule Tests

**Type:** Skill (imperative prompt)
**Input:** Solution manifest (from `analyze-solution-structure.prompt.md`) + target entity name
**Output:** A complete `<entity>-business-rules.test.ts` Playwright test file

---

## Instructions for the AI Agent

You are generating a Playwright test file for Business Rules defined on a
Model-Driven App entity. Each test triggers a rule's condition and asserts the
observable outcome of its actions.

**Before starting:** Read these instruction files:
- `docs/context-engineering/instructions/00-unpacked-solution-overview.md`
- `docs/context-engineering/instructions/01-mda-form-testing.md`
- `docs/context-engineering/instructions/03-mda-business-rules-testing.md`

---

## Inputs

Replace all placeholders with actual values before sending this prompt:

```
MANIFEST: <paste the full JSON manifest from analyze-solution-structure here>
TARGET_ENTITY: <entity logical name, e.g. nwind_order>
APP_NAME: <the display name of the Model-Driven App>
OUTPUT_FILE: packages/e2e-tests/tests/<subdirectory>/<entity>-business-rules.test.ts
```

## Steps

### Step 1 — Find Business Rules for the Target Entity

From `manifest.businessRules[]` where `entityName === TARGET_ENTITY`, collect all rules.

If no rules exist, output a file with a single `test.skip` block explaining this.

### Step 2 — Classify Rules by Trigger Scope

Split the rules into two groups:

- `createOnlyRules`: `triggerOnCreate === true && triggerOnUpdate === false`
- `updateOnlyRules`: `triggerOnCreate === false && triggerOnUpdate === true`
- `bothRules`: `triggerOnCreate === true && triggerOnUpdate === true`

Rules in `createOnlyRules` and `bothRules` need a new-record `beforeEach`.
Rules in `updateOnlyRules` and `bothRules` need an existing-record `beforeEach`.

If all rules are `updateOnlyRules`, a single `beforeEach` with the 5-row scan suffices.
Otherwise, structure tests into `test.describe` blocks per trigger type (see Step 6).

### Step 3 — Map Each Action Type to Its Assertion

For each action in each rule, determine the assertion method from instruction 03
Section 2.3:

| Action type | Assertion code |
|---|---|
| `SetFieldValue` | `expect(await getEntityAttribute(page, '<attr>')).toBe(<value>)` |
| `SetVisibility` | `expect(await executeInFormContext(page, Xrm => Xrm.Page.getControl('<attr>')?.getVisible())).toBe(<bool>)` |
| `SetRequiredLevel` | `expect(await modelDrivenApp.form.getFieldRequiredLevel('<attr>')).toBe('<level>')` |
| `SetFieldDisabled` | `expect(await executeInFormContext(page, Xrm => Xrm.Page.getControl('<attr>')?.getDisabled())).toBe(<bool>)` |
| `LockField` | Same as `SetFieldDisabled` with `true` |
| `ShowError` | try/catch notification check (see instruction 03 Section 4.6) |
| `ShowMessage` | try/catch notification check (see instruction 03 Section 4.6) |

### Step 4 — Determine Trigger Values for Each Condition

For each condition `{ lhsAttribute, operator, rhsValue }`, derive the trigger value:

| Operator | Trigger value for the test |
|---|---|
| `Equal` | `rhsValue` (parse to the correct JS type: number, string, boolean) |
| `NotEqual` | A value clearly different from `rhsValue` |
| `GreaterThan` | `Number(rhsValue) + 1` |
| `LessThan` | `Number(rhsValue) - 1` |
| `GreaterThanOrEqual` | `Number(rhsValue)` |
| `LessThanOrEqual` | `Number(rhsValue)` |
| `Contains` | A string that includes `rhsValue` as a substring |
| `BeginsWith` | `rhsValue + '-suffix'` |
| `Null` | `null` |
| `NotNull` | Any non-null value appropriate for the field type |

Also derive a **non-trigger value** (the opposite, to test the inverse condition if the
rule has a visible "else" branch, e.g. `SetVisibility` toggling back to `true`).

### Step 6 — Generate `test.describe` Blocks

#### For update-only and both-trigger rules (existing record):

```typescript
test.describe.serial('<EntityDisplayName> Business Rules — Existing Record', () => {
  let appProvider: AppProvider;
  let modelDrivenApp: ModelDrivenAppPage;

  test.beforeEach(async ({ page, context }) => {
    appProvider = new AppProvider(page, context);
    await appProvider.launch({
      app: APP_NAME,
      type: AppType.ModelDriven,
      mode: AppLaunchMode.Play,
      skipMakerPortal: true,
      directUrl: MODEL_DRIVEN_APP_URL!,
    });
    modelDrivenApp = appProvider.getModelDrivenAppPage();
    await modelDrivenApp.navigateToGridView(ENTITY_NAME);
    await page.waitForTimeout(3000);

    let found = false;
    for (let row = 0; row < 5; row++) {
      await modelDrivenApp.grid.openRecord({ rowNumber: row });
      await page.waitForURL(/pagetype=entityrecord/, { timeout: 15_000 });
      await page.waitForTimeout(2_000);
      const isWritable = await page.evaluate(() => {
        const entity = (window as any).Xrm?.Page?.data?.entity;
        if (!entity) return false;
        let count = 0;
        try { entity.attributes.forEach(() => { count++; }); } catch { /* ignore */ }
        if (count === 0) return false;
        try { return entity.isValid() === true; } catch { return false; }
      });
      if (isWritable) { found = true; break; }
      await modelDrivenApp.navigateToGridView(ENTITY_NAME);
      await page.waitForTimeout(2_000);
    }
    if (!found) throw new Error('No writable record found in first 5 rows');
  });

  // ... emit test blocks for update-only and both-trigger rules here ...
});
```


### Step 7 — Emit One Test Block per Rule

For each Business Rule, emit:

```typescript
  test('BR: <rule.name> — <condition summary>: should <action summary>', async ({ page }) => {
    // Step A: Capture original field values (for rollback)
    const originalValues: Record<string, any> = {};
    // For each lhsAttribute in the condition:
    originalValues['<lhsAttribute>'] = await getEntityAttribute(page, '<lhsAttribute>');

    // Step B: Trigger the condition
    // For each condition (AND all conditions):
    await setEntityAttribute(page, '<lhsAttribute>', <trigger_value>);

    // Wait for Business Rule engine to process
    await page.waitForTimeout(500);

    // Step C: Assert each action's outcome
    // (use the assertion code from Step 3)

    // Step D: Rollback (restore original values to keep tests independent)
    for (const [field, value] of Object.entries(originalValues)) {
      try {
        await setEntityAttribute(page, field, value);
      } catch {
        // Field may have become read-only — ignore rollback errors
      }
    }
    await page.waitForTimeout(300);
  });
```

**Naming convention for test descriptions:**
- Condition summary: `when <lhsAttribute> <operator> <rhsValue>`
- Action summary: one verb phrase per action, joined with " and "

Example: `'BR: Require Notes — when priority Equal 3: should set customernotes to required'`

### Step 8 — Handle Compound Conditions

For rules with multiple `<Condition>` elements (AND logic):
- Set **all** trigger attributes in sequence before asserting.
- Name the test to mention all conditions: `'when A Equal 1 and B Equal 2'`

For OR logic (check `LogicalOperator` attribute if present in manifest):
- Emit separate test blocks for each OR branch.

### Step 9 — Handle Inverse Conditions (if rule has else branch)

Some rules implicitly reset fields when the condition is no longer met (e.g., visibility
toggled back). If you see a corresponding SetVisibility with opposite value or the rule
has both positive and negative actions listed, emit an inverse test:

```typescript
  test('BR: <rule.name> — condition NOT met: should <opposite action summary>', async ({ page }) => {
    await setEntityAttribute(page, '<lhsAttribute>', <non_trigger_value>);
    await page.waitForTimeout(500);
    // Assert the opposite / default state
  });
```

Only emit the inverse test if you can clearly determine the expected non-triggered state
from the manifest or rule logic.

### Step 10 — Add `test.afterAll` Cleanup Comment

```typescript
  // NOTE: Tests in this suite revert field values after each test using the
  // rollback pattern in Step D of each test. No additional afterAll cleanup needed
  // unless create-scoped tests produced new records that must be deleted.
```

If create-scoped tests produce new records, add:

```typescript
  test.afterEach(async ({ page }) => {
    try {
      await page.evaluate(() => {
        const entity = (window as any).Xrm?.Page?.data?.entity;
        if (!entity) return;
        const name = entity.getEntityName();
        const id = entity.getId().replace(/^\{|\}$/g, '');
        if (!id || id === '00000000-0000-0000-0000-000000000000') return;
        return (window as any).Xrm.WebApi.deleteRecord(name, id);
      });
    } catch {
      // Record may not have been created or already deleted — ignore
    }
  });
```

### Step 11 — Close All Describe Blocks

---

## Output Rules

- Output a **single TypeScript file** only — no prose, no markdown fences.
- Every `page.waitForFunction` must pass `undefined` as second arg and `{ timeout }` as third arg.
- Every `executeInFormContext` call must use optional chaining on `getControl()?.getMethod()`.
- Every `setFormNotification` observation must be wrapped in try/catch.
- Do not use `page.locator()` or `page.fill()` for Dataverse form fields.
- Use `test.describe.serial` blocks (not `test.describe`).
- Test names must follow the BR naming convention in Step 7.
- Remove any unused imports.
- If there are no rules for `TARGET_ENTITY`, output:
  ```typescript
  import { test } from '@playwright/test';
  test.skip(true, 'No Business Rules found for entity: <TARGET_ENTITY>');
  ```
