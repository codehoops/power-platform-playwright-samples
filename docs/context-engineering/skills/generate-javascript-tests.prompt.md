# Skill: Generate JavaScript Event Handler Tests

**Type:** Skill (imperative prompt)
**Input:** Solution manifest (from `analyze-solution-structure.prompt.md`) + target web resource file name + JS source file content
**Output:** A complete `<webresource>-events.test.ts` Playwright test file

---

## Instructions for the AI Agent

You are generating a Playwright test file for JavaScript event handlers registered on a
Model-Driven App form. Tests must verify **observable outcomes** only — never re-implement
the business logic from the handler in the test body.

**Before starting:** Read these instruction files:
- `docs/context-engineering/instructions/00-unpacked-solution-overview.md`
- `docs/context-engineering/instructions/01-mda-form-testing.md`
- `docs/context-engineering/instructions/02-mda-javascript-testing.md`

---

## Steps

### Step 1 — Find the Web Resource Entry in the Manifest

From `manifest.webResources[]` where `uniqueName === TARGET_WEBRESOURCE`, collect:
- `referencedBy[]`: the list of `{ entityName, formName, eventName, attributeName, functionName }` objects

If `referencedBy` is empty, the web resource is not bound to any active form handler —
output a file with a single `test.skip` explaining this.

### Step 2 — Determine the Target Entity

All `referencedBy` entries should share the same `entityName`. If they reference
multiple entities, generate separate `test.describe` blocks per entity.

Use the primary entity's logical name as `ENTITY_NAME`.

### Step 3 — Read the JS Source

Scan `JS_SOURCE` for each function listed in `referencedBy[].functionName`. For each:

1. Identify what the function reads (which attributes, via `getAttribute`)
2. Identify what the function writes (which attributes, `setValue` / `fireOnChange`)
3. Identify side-effects:
   - `setVisible` / `setVisibleAll` calls
   - `setRequiredLevel` calls
   - `setDisabled` calls
   - `setFormNotification` / `clearFormNotification` calls
   - `Xrm.WebApi` async calls (retrieveMultipleRecords, createRecord, etc.)
   - `Xrm.Navigation` calls
4. For each side-effect, note the **target attribute/control** and the **expected new state**.

Do **not** re-implement the logic. Use the function's actual inputs and outputs to
craft assertions with concrete known values.

### Step 4 — Group Events by Type

Separate `referencedBy` entries into three lists:
- `onloadHandlers`: `eventName === "onload"`
- `onchangeHandlers`: `eventName === "onchange"` (note the `attributeName`)
- `onsaveHandlers`: `eventName === "onsave"`

### Step 5 — Generate the File Header

```typescript

/**
 * JavaScript Event Handler Tests — <TARGET_WEBRESOURCE>
 *
 * Tests the observable outcomes of the event handlers in <TARGET_WEBRESOURCE>.js
 * registered on the <EntityDisplayName> main form.
 * Auto-generated by generate-javascript-tests skill.
 *
 * Prerequisites:
 *   - MODEL_DRIVEN_APP_URL set in .env
 *   - npm run auth:mda:headful completed
 */

import { test, expect } from '@playwright/test';
import {
  AppProvider,
  AppType,
  AppLaunchMode,
  ModelDrivenAppPage,
  getEntityAttribute,
  setEntityAttribute,
  saveForm,
  isFormDirty,
  executeInFormContext,
} from 'power-platform-playwright-toolkit';

const MODEL_DRIVEN_APP_URL = process.env.MODEL_DRIVEN_APP_URL;
const ENTITY_NAME = '<ENTITY_NAME>';
const APP_NAME = '<APP_NAME>';

if (!MODEL_DRIVEN_APP_URL) {
  throw new Error('MODEL_DRIVEN_APP_URL environment variable is required.');
}
```

### Step 6 — Generate `test.describe.serial` and `beforeEach`

Use the same editable-record scan pattern as the form tests skill (Step 4 of
`generate-mda-form-tests.prompt.md`) — copy it exactly.

### Step 7 — Emit `onload` Tests

For each handler in `onloadHandlers`, emit one `test` block that:
1. Opens a comment explaining which function is being tested.
2. Asserts the **initial state** the handler sets on load.
3. Uses `executeInFormContext` for all Xrm-side assertions.

Example structure:
```typescript
  // Tests for onload handler: <functionName>
  test('onload: should <describe expected initial state set by handler>', async ({ page }) => {
    // Form was opened in beforeEach — assert the handler's expected outcome
    const <sideEffectField> = await executeInFormContext(page, (Xrm) =>
      Xrm.Page.getControl('<targetControl>')?.getVisible()
    );
    expect(<sideEffectField>).toBe(<expectedValue>);
  });
```

If the handler has multiple distinct side-effects (e.g. sets visibility on 3 fields),
emit one test per side-effect group, not one per attribute.

### Step 8 — Emit `onchange` Tests

For each handler in `onchangeHandlers`, emit one test block per **distinct trigger
condition** visible in the JS source. Each test:

1. Sets the triggering attribute to its condition value using `setEntityAttribute`.
2. Waits 1000ms for the handler to settle (`await page.waitForTimeout(1000)`).
3. Asserts the side-effect using `executeInFormContext` or `getEntityAttribute`.
4. If the handler has an else/else-if branch, emit a second test for the alternative.

```typescript
  // Tests for onchange handler: <functionName> (attribute: <attributeName>)
  test('onchange(<attributeName>): should <describe outcome when condition is met>', async ({ page }) => {
    await setEntityAttribute(page, '<attributeName>', <trigger_value>);
    await page.waitForTimeout(1000);
    const <result> = await executeInFormContext(page, (Xrm) =>
      Xrm.Page.getControl('<targetControl>')?.<observationMethod>()
    );
    expect(<result>).toBe(<expected>);
  });

  test('onchange(<attributeName>): should <describe outcome when condition is NOT met>', async ({ page }) => {
    await setEntityAttribute(page, '<attributeName>', <non_trigger_value>);
    await page.waitForTimeout(1000);
    const <result> = await executeInFormContext(page, (Xrm) =>
      Xrm.Page.getControl('<targetControl>')?.<observationMethod>()
    );
    expect(<result>).toBe(<opposite_expected>);
  });
```

**Important:** If `setEntityAttribute` is called for a field that cannot be written
(read-only), skip that test and add a `test.skip` with an explanation.

### Step 9 — Emit `onsave` Tests

For each handler in `onsaveHandlers`, emit one test that:
1. Sets up the triggering precondition.
2. Calls `saveForm(page)`.
3. Waits 1500ms.
4. Asserts the expected post-save state (dirty flag, notification, field value).

For handlers that **block** the save:
```typescript
  expect(await isFormDirty(page)).toBe(true); // still dirty = save was blocked
```

For form notifications, always wrap in try/catch per instruction 02 Section 6.3:
```typescript
  try {
    const notifs = await executeInFormContext(page, (Xrm) =>
      (Xrm.Page.ui.getFormNotifications?.() ?? []).map((n: any) => ({
        level: n.getLevel(),
        message: n.getMessage(),
      }))
    );
    expect(notifs.some((n: any) => n.level === 'WARNING')).toBe(true);
  } catch (err) {
    console.log('⚠️ Notification check skipped (UI container not ready):', (err as Error).message);
  }
```

### Step 10 — Emit `test.afterEach` Cleanup (if any test modifies data)

If any test writes attribute values that persist, add:

```typescript
  test.afterEach(async ({ page }) => {
    // Revert any changes to avoid polluting subsequent tests
    // (add specific reverts based on what was changed)
  });
```

### Step 11 — Close the Describe Block

```typescript
}); // end test.describe.serial
```

---

## Output Rules

- Output a **single TypeScript file** only — no prose, no markdown fences.
- Every `executeInFormContext` call must handle the case where `getControl(field)` returns
  `null` (use optional chaining: `?.getVisible()`).
- Every `setFormNotification` observation must be wrapped in try/catch.
- Every `page.waitForFunction` must have `undefined` as second arg and `{ timeout }` as
  third arg.
- Do not use `page.locator()` or `page.fill()` for Dataverse form fields.
- Test names must follow the pattern: `'<eventName>(<triggerAttribute>): <outcome description>'`
- Use `test.describe.serial` (not `test.describe`).
- Remove any unused imports.
